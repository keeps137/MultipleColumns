# 幽灵层模组 · 测试宿主 v0.2.1（已通过 v160.7 官方 jar 真实编译，0 错误）

给宿主（测试方块：砂×4+氢→硅，需电需热）叠加虚拟生产列，多批并行。
每批一条虚拟账目：料/液/电/热四科目「攒账 → 结清 → 批内只花账内 → 完工注销」。

> 模组名「幽灵层测试宿主」，包名 `ghostfixture`，jar 为 `GhostLayerFixture.jar`——
> 与另一条开发线的 `GhostLayer` 主模组（同名包名会冲突）可以同时安装，作为联调夹具使用。

## 终版设计条款（已拍板）

1. **账目模型：四科目开工一次结清（终版，不再改）**。所有科目在开工前一次付清，批内只花账内虚拟账；
   真实电网/管线/热力线只在结清那一刻被碰一次。不采用"液体/电/热逐帧实扣"方案。
2. **整批用量单位约定**：`craftTime`、`ConsumeLiquid.amount`、`ConsumePower.usage` 的单位都是**刻（帧）**，
   不是秒。整批用量 = 每刻用量 × `craftTime`，任何 `/60` 换算都是错的（v0.1.x 的教训）。
3. **动态效率快照**：材料属性效率（可燃/放射/爆炸等）在结清那一刻读一次、乘进整批产出账并锁进账本；
   批内不重算、不回滚——中途换燃料或改地形，等这批跑完再生效。地形属性加成（热泉等）将来支持连续型
   建筑时遵循同一原则：开工时读一次地形加成锁进账本。
4. **拆宿主按原版拆除倍率返还**账内余额；被摧毁不返还；液体不返还。

## 怎么编译（GitHub Actions）

1. 把整个 `ghost-layer-mod` 文件夹上传到你的 GitHub 新仓库（网页端 Add file 一路拖进去也行）。
2. 把仓库里的 `github-workflow-build.yml` 移动成 `.github/workflows/build.yml`
   （GitHub 网页：Add file → Create new file，路径填 `.github/workflows/build.yml`，把文件内容粘进去提交）。
3. push 后 Actions 会自动编译，跑完在 Artifacts 里下载 `GhostLayerFixture.jar`。
4. 把 jar 放进手机 Mindustry 的 `mods/` 文件夹，重启游戏。

## 游戏里怎么玩

1. 造一台「幽灵宿主」（合成类，铜30+铅20+硅15）。
2. 点它，配置栏里有「幽灵层 0/100」按钮 → 打开面板。
3. 点「+ 扩列」加列：**每列消耗与本体等价的建造材料（铜30+铅20+硅15），从主核心扣**；列会自动攒账（砂/氢/电/热四科目）、开工、生产、出货。
4. 断料/断电/热量不够 → 筹备列停下攒账，**在产列照跑（无总闸门）**。
5. 宿主缓冲快满 → 批跑满的列锁在「出货」，腾出空间自动补塞。
6. 手动拆宿主：退还未花完的账（进主核心）；被摧毁不返还（与原版一致）。

## 第一版的简化（都写在代码注释里）

- 电力：有电池的电网**结清时真扣**整批能量（`useBatteries`，预留1点，扣不动继续攒）；无电池的电网走
  "结清时校验富余"的退路方案（拍板过的退路，不实扣）。
- 热量：原版热力**无存储，物理上无法预付**——结清时校验一次 + 在产阶段逐帧校验，热量不足批停进度冻结
  （唯一在批内仍受实时约束的科目，属热力科目对结清口径的天然例外）。
- **电已实扣、热受批内校验**：有电池电网的批内电费为真扣（见上），不再"白付"；热受批内逐帧校验约束。
  拆宿主时电费不返还（能量已付给电网，无法退回核心），物品照常按比例返还。
- 扩列费从主核心扣、不返还：没有删列入口；拆宿主时列费随本体消失（原版只返还本体材料）。
- 液体返还：拆除时液体部分暂不返还。
- 拆宿主返还进主核心（team.core()），超出核心容量部分丢弃；换图/清档也会触发一次返还，属已知边角。
- 存档：自定义存档块，版本字节不认识就按长度整块跳过（不弄坏后面模组的存档）。
- 存档块名 `ghost-fixture`：与主模组（块名不同）可同时安装，互不覆盖。
- 批内进度语义（已拍板）：在产列进度用 `delta()` 推进——继承宿主超速，**不**继承实时效率；
  结清过的批不受开工后断电/掉热影响，照跑出货。这与"批内只花账内"是同一条语义。
- 液体容量注意事项：整批液量 = amount × craftTime，而方块容量按 10 × amount × 60 推导，
  因此 craftTime 超过 600 刻的方块整批液量会超过宿主容量——主模组处理长配方时需解决，
  夹具（craftTime=80）不受影响。
- 时间分片：骨架留了，万列级实测卡了再启用。
- 多人：自定义存档默认不同步给客户端，v1 按单机设计。

## 文件结构

- `src/ghostfixture/GhostLayerMod.java` —— 模组入口（extends Mod）：注册方块、存档块、面板刷新
- `src/ghostfixture/GhostHostBlock.java` —— 测试宿主方块 + 内部建筑类（列扫描、层叠门控、入口按钮、拆宿主返还）
- `src/ghostfixture/GhostColumn.java` —— 幽灵列：状态机、攒账、出货锁定
- `src/ghostfixture/BatchAccount.java` —— 本批账目：四科目、序列化、返还
- `src/ghostfixture/RecipeProbe.java` —— 配方探针：宿主消费器 → 账目模板（整批用量 = 每刻用量 × craftTime）
- `src/ghostfixture/GhostSaveChunk.java` —— 存档块：坐标键控、版本字节+载荷长度
- `src/ghostfixture/GhostPanel.java` —— 面板：逐列状态、扩列
- `sprites/ghost-host.png` —— 方块贴图
- `github-workflow-build.yml` —— 编译工作流（挪进 .github/workflows/）
- `build.gradle` / `settings.gradle` / `mod.hjson`

## 编译验证说明

- 本版已用官方 v160.7 发布 jar（最新版线，与你手机上 Mindustry X 的基底一致）在本地 javac 全量编译，0 错误。
- jitpack 对 v150+ 的依赖包已失效，构建脚本改为直接从官方 GitHub 发布页下载游戏本体 jar 作编译依赖（已同步改好）。
- **安卓 dex 已内建**：构建脚本会用 D8 把字节码转成安卓格式并塞进 jar（classes.dex），手机端直接可用，不需要手动转换。
- `minGameVersion: 160`：v160 起原版对 Java 模组要求最低版本 154，声明 146 会被直接拒载。
- 方块贴图 `sprites/ghost-host.png` 已内含（代码绘制），进游戏不再是错误方块。
- 原版建筑类是绑定方块实例的内部类，所以宿主建筑以内部类形式挂在 GhostHostBlock 里（buildType = GhostHostBuild::new）。
